# Контур — сигналы крипторынка Bybit

Локальная панель на FastAPI, SQLite и React. Сервис получает публичные котировки Bybit, ищет фигуры на закрытых свечах и ведёт виртуальную симуляцию. Адаптер Bybit не отправляет реальные ордера.

## Быстрый запуск

Нужны Python 3.12+ и Node.js 20.19+ (или 22.12+). В PowerShell из папки проекта выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Скрипт создаёт виртуальное окружение, устанавливает зависимости, собирает интерфейс и запускает сервис на http://127.0.0.1:8000. Для повторного запуска без установки и сборки используйте `-SkipInstall`.

При запуске из Codex сервису нужен сетевой доступ к Bybit: запускайте скрипт вне изолированной среды с сетевыми ограничениями. Для штатной остановки нажмите Ctrl+C и дождитесь завершения процесса. Если сеть временно недоступна, панель остаётся доступной и автоматически восстанавливает историю после подключения.

Симуляция работает без API-ключей с базовой комиссией Bybit VIP 0. Для получения персональной ставки можно задать `BYBIT_FEE_MODE=account` и read-only ключи в локальном `.env`. Ключи не попадают в интерфейс или API-ответы.

## Сигналы и вход

В панели две вкладки: «Сигналы» и «Ранние сигналы». Ранние фигуры строятся по закрытым свечам с подтверждёнными экстремумами; их исходная геометрия остаётся неизменной. Пересечение границы минимум на один шаг цены сразу отмечается по тикеру. Возврат цены внутрь снимает предварительный пробой, а новое пересечение в той же свече обновляет ту же карточку. Подтверждение создаётся только после закрытия свечи: порог стандартного профиля — 0,1 ATR, расширенного — 0,05 ATR.

Карточки отдельно показывают границу пробоя, последнюю котировку и допустимую зону входа. Общая оценка учитывает шаг цены, свежесть котировки до 5 секунд, комиссию, проскальзывание, funding и настроенный минимум чистого RR. Если даже при входе у границы пробоя потенциальная прибыль до цели слишком мала относительно риска до стопа, допустимой зоны нет; карточка объясняет требуемое соотношение прибыли к риску с учётом расходов. «Вход упущен» означает, что цена вышла за существовавшую зону. Если котировка или данные о расходах устарели, вход не помечается доступным. Ранние карточки предназначены для ручной оценки; виртуальные входы сохраняют прежний исторический допуск стратегии. Реальные ордера не отправляются.

Для ручных скальперских сделок ранние наблюдения отдельно показывают план на 15–30 минут по закрытым 5-минутным свечам: локальный стоп, ближайшую цель, чистое RR и оценку расходов. План ждёт подтверждения закрытием 5-минутной свечи за границей и требует минимум 1,5:1 после расходов. При отсутствующих локальных уровнях, устаревших свечах, котировке или стакане вход помечается неподходящим либо ожидающим данные. Это отдельная подсказка для ручной оценки; порог и уровни виртуальной стратегии она не меняет.

Сигналы сортируются по времени закрытия пробойной свечи. Ранние наблюдения сортируются по `event_at`; карточка показывает это же событие: формирование фигуры, первое пересечение или подтверждение пробоя. Для парных направлений время берётся по более новому событию группы. Стабильный порядок лент — `(event_at DESC, id DESC)`.

## API и обновления

| Маршрут | Назначение |
|---|---|
| `GET /api/snapshot?view=summary` | Краткий снимок первых 50 сигналов и 50 наблюдений; без параметра сохраняется полный формат |
| `GET /api/signals?limit=50&view=summary` | Краткая лента сигналов; `status`, `before_time`, `before_id` |
| `GET /api/setups?limit=50&view=summary` | Краткая лента ранних наблюдений с курсором |
| `GET /api/signals/{id}/context` | Контекст подтверждённого сигнала |
| `GET /api/setups/{id}/context` | Контекст раннего наблюдения |
| `GET /api/forecast-outcomes` | Итоги прогнозов через 5, 15 и 30 минут и диагностическое сравнение фильтров |
| `GET /api/state`, `GET /api/trades` | Состояние симуляции и сделки |
| `GET /api/candles/{symbol}/{tf}` | Свечи графика и загрузка диапазона |

Существующие REST-маршруты сохраняют массивы ответов. Фильтрация применяется до ограничения страницы. Старый `/ws` и `/ws?v=2` поддерживаются. Новый клиент подключается к `/ws?v=3`: он получает краткий снимок, затем компактные изменения с `stream_id` и возрастающим `revision`. При пропуске версии клиент запрашивает новый снимок. Изменения сценария публикуются сразу, котировки объединяются до четырёх раз в секунду; медленные браузеры получают отдельную очередь отправки, а при отключении WebSocket клиент использует REST.

Время события хранится в биржевых timestamp без повторной поправки часового пояса. Интерфейс показывает время Москвы с секундами, возраст котировки и задержку доставки отдельно от задержки обработки.

## Архитектура и хранение

`backend/service.py` координирует независимые этапы: приём потоков, очередь закрытых свечей, расчёт контекста и публикацию. Распознавание фигур, правила стратегии, оценка решения, качество рыночных данных, сравнение стаканов и публикация вынесены в отдельные модули. Живые закрытия обслуживают 16 лёгких обработчиков, восстановление — два отдельных; события каждого инструмента и таймфрейма идут последовательно. Число процессов распознавания — `min(4, max(1, CPU − 2))`. Курсор свечи и переходы известных наблюдений записываются до публикации; восстановленные закрытия имеют отдельную очередь. Повторные события одного потока сохраняют порядок.

SQLite использует пакетный поток записи и независимые короткие соединения чтения. Перед миграцией существующей базы создаётся согласованная проверенная копия средствами SQLite backup; схема отслеживается через `PRAGMA user_version` и теперь имеет версию 7. На одну базу разрешён только один процесс сканера. Минутные агрегаты с происхождением и покрытием хранятся 30 дней; старые записи отмечаются как качество неизвестно.

## Проверки

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
npm.cmd --prefix frontend run build
.\.venv\Scripts\python.exe tools\ui_smoke.py
.\.venv\Scripts\python.exe tools\load_smoke.py
```

Браузерная проверка использует изолированную базу в памяти и проверяет обе ленты, фильтр, график, переподключение WebSocket и узкий экран. Установите необязательные зависимости и Chromium один раз:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m playwright install chromium
```

Диагностика задержек и свежести потоков доступна в `GET /api/state` в объекте `scanner_diagnostics`. Задержка доставки от биржи измеряется отдельно.

Документация Bybit: [WebSocket kline](https://bybit-exchange.github.io/docs/v5/websocket/public/kline), [тикеры](https://bybit-exchange.github.io/docs/v5/websocket/public/ticker).
